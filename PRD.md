## 2. Executive Summary

**CardPulse SaaS** is a specialized, multi-tenant commercial ID card production and management platform engineered for printing hubs (e.g., Yash Enterprises) and institutional groups. The platform automates the end-to-end lifecycle of student identification card creation—from tenant quota provisioning and template design to tokenized public link generation for zero-login student form submissions, automated photo quality/storage validations, watermarked live canvas previews, proof sample review, and duplex A4 print sheet layout generation.

### Key Value Pillars
1. **Zero-Login Distribution Model**: Schools and colleges do not require user accounts or login portals. They simply receive tokenized public form links generated by the Tenant Admin and forward them directly to students/parents.
2. **Real-time Watermarked Canvas Preview**: Students fill in their information and immediately see a live, watermarked HTML5 Canvas preview of their official ID card (Front & Back) before submitting.
3. **Storage & Print Safeguards**: Automated client-side photo framing guidelines, format validation (`JPG`, `PNG`, `WEBP`), file size ceiling (5MB limit), and minimum print resolution checks (minimum 200x200 px).
4. **Duplex A4 Batch Production Pipeline**: Automated auto-grid page imposition with corner crop marks for mass printing and cutting.

## 3. Problem Statement

### Existing Industry Pain Points
* **Spreadsheet & Email Chaos**: Educational institutions collect student data and photos via manual Google Forms or email attachments, leading to corrupted filenames and lost entries.
* **Photo Quality & Aspect Ratio Issues**: Students submit cropped selfies, low-resolution images, or inappropriate file sizes that strain cloud storage and result in blurry physical ID cards.
* **Complex Portal Onboarding**: School administrators resist managing username/password credentials for single-use annual ID card collection.
* **High Proofing Round-Trips**: Printing hubs spend weeks mailing physical proof samples back and forth to schools to fix simple typos or misaligned fields.
* **Manual Print Imposition**: Print operators spend hours manually arranging hundreds of ID cards onto A4 sheets with crop marks in graphic software.

---

## 4. Project Objectives

* **Zero-Login Form Distribution**: Eliminate 100% of school user account overhead by utilizing tokenized URL links.
* **Reduce Rejected Prints by 95%**: Enforce strict photo checks (format, 5MB limit, resolution) at the moment of student submission.
* **Instant Visual Confirmation**: Provide students with live, watermarked Front & Back ID card rendering.
* **Automated Print Preparation**: Generate duplex A4 sheets with crop marks directly from finalized batches.
* **Multi-Tenant Scalability**: Support print quota limits, custom lanyards, and master-synced custom fields per institutional tenant.

## 8. Detailed System Modules & Feature Breakdown

### 8.1 Module 1: Super Admin Management Console
* **Module Purpose**: Central SaaS platform governance, print production hub provisioning, and global quota limits.
* **Features**:
  - **Print Hub Onboarding**: Create and manage commercial printing hubs (Tenants).
  - **Production Quota Allocation**: Set maximum ID printing limits per tenant (e.g. 15,000 cards).
  - **Global System Status Controls**: Maintenance toggles and platform usage analytics.

### 8.2 Module 2: Tenant Admin Operations Hub (Yash Enterprises Hub)
* **Module Purpose**: Full operational suite for managing institutions, template designs, field schemas, batch form links, data inspection, proofing, and duplex A4 print sheet imposition.
* **Sub-Modules & Features**:
  1. **Schools & Colleges Directory**: Onboard institutions with code, admin details, and assigned template.
  2. **ID Card Template Library**:
     - Upload front/back background graphic artwork PNG/PDF files.
     - Define photo zone coordinates, size, and shape (`rounded`, `oval`, `rectangle`).
     - Map text placeholders with custom font sizes, colors, alignments, and weights.
  3. **Master & Custom Data Field Builder**:
     - Define global master fields (`fullName`, `rollNo`, `className`, `division`, `dob`, `bloodGroup`, `phone`).
     - Add institution-specific custom fields (`Hostel Pass`, `Bus Route Stop`, `Lab Group ID`).
  4. **Class Batch & Tokenized Link Generator**:
     - Create academic class/division folders (e.g., `Computer Science - Section A`).
     - Configure field checklists for form submission.
     - Auto-generate tokenized public URLs (`http://localhost:3000?form=public&school=sch-1&batch=batch-1...`).
     - Instant copy-link functionality for email/WhatsApp forwarding to schools.
  5. **Real-Time Submissions Intake Directory**:
     - 3-Level hierarchical drill-down navigation: `Schools Directory` → `Class Batch Folders` → `Student Records Table`.
  6. **Interactive Canvas Proofing Studio**:
     - Live Photoshop-style drag-and-drop tool to adjust photo framing and nudge text positions across a batch.
     - Toggle front/back card views with lanyard ribbon preview.
  7. **Generation & Print Pipeline**:
     - Direct bulk generation trigger pushing finalized data into print status without approval bottlenecking.
     - Duplex A4 print sheet layout engine auto-arranging cards with corner crop/cut marks.

### 8.3 Module 3: Zero-Login Public Student Form & Live Canvas Preview
* **Module Purpose**: Zero-friction student/parent data entry portal with live visual confirmation and storage safeguards.
* **Features**:
  - **Tokenized URL Data Auto-Fill**: Parses `school`, `batch`, `class`, and `div` directly from query params.
  - **Composite Uniqueness Check**: Prevents duplicate entries matching `Roll Number` + `Class`.
  - **Guided Dual Photo Input**: File upload OR live camera webcam capture with face-positioning oval overlay.
  - **Strict Storage & Quality Validation**:
    - Format restriction: `JPG`, `PNG`, `WEBP`.
    - File size limit: Hard ceiling of 5MB.
    - Print resolution check: Minimum 200px × 200px required.
  - **Real-Time Watermarked Canvas ID Card Preview**:
    - Renders exact ID card as data is typed with front/back toggle.
    - Diagonal translucent red overlay watermark: `"PREVIEW ONLY / UNAPPROVED"`.

## 9. Functional Requirements Specification

### 9.1 Public Student Form & Live Preview (`FR-STU`)

#### FR-STU-001: Tokenized Public Access
* **Description**: The system shall allow students to access the registration form via a public tokenized URL containing `schoolId`, `batchId`, `className`, and `division` query parameters without requiring login.
* **Validation**: If parameters are missing or invalid, default to baseline active institution settings.

#### FR-STU-002: Real-time Watermarked ID Card Preview
* **Description**: The student form shall render an interactive HTML5 Canvas displaying a live preview of the student's ID card as fields are typed.
* **Requirements**:
  - Must render Front and Back sides via toggle controls.
  - Must display a prominent translucent red diagonal watermark text: **"PREVIEW ONLY / UNAPPROVED"**.
  - Must reflect real-time updates for `Full Name`, `Roll Number`, `Class/Department`, `Blood Group`, `Phone`, and `Photo`.

#### FR-STU-003: Strict Photo Validation
* **Description**: The system shall validate uploaded or camera-captured photos before allowing form submission.
* **Validation Rules**:
  - **Allowed Formats**: `image/jpeg`, `image/png`, `image/jpg`, `image/webp`.
  - **Max File Size**: 5MB ceiling to prevent storage overflow.
  - **Min Resolution**: 200px width × 200px height minimum for print sharpness.
  - **Feedback**: Display clear UI error banners when validation fails.

---

### 9.2 Tenant Management & Link Generation (`FR-TNT`)

#### FR-TNT-001: Class Batch & Link Management
* **Description**: The Tenant Admin shall be able to create Class Batches (e.g., "Computer Science - Section A") and publish tokenized form links.
* **Actions**:
  - Define Class Name, Division, Academic Year.
  - Select included Master Data Fields and add custom fields (e.g., "Bus Route Stop").
  - Auto-generate public tokenized link with instant copy-to-clipboard functionality.

#### FR-TNT-002: Direct Bulk Card Generation & Printing Pipeline
* **Description**: The system operates without an interactive approval gating bottleneck. Once students submit their registration data via tokenized public links, data is stored directly under the tenant.
* **Behavior**:
  - When the Tenant Admin triggers **Bulk Card Generation**, all batch entries are automatically merged with assigned templates and pushed directly to `Printing` status.
  - Watermarks are automatically removed for high-resolution print output during A4 sheet imposition.

#### FR-TNT-003: Duplex A4 Print Sheet Imposition
* **Description**: The system shall auto-arrange approved batch cards into an A4 duplex print grid (front side sheet & back side sheet) complete with corner crop/cut marks.

## 10. Non-Functional Requirements

### 10.1 Performance & Responsiveness
* **Canvas Render Latency**: HTML5 Canvas redraw time shall be `< 50ms` upon keystroke.
* **Client-side Image Compression**: Photo processing and canvas scaling executed in-browser to minimize network bandwidth.

### 10.2 Security & Storage Protection
* **Storage Shield**: 5MB hard limit per photo submission prevents server disk exhaustion attacks.
* **Input Sanitization**: All form inputs stripped of script tags before canvas rendering.

---

## 11. Acceptance Criteria

A release is considered accepted when:
1. **Public Form**: Students can access the tokenized link without logging in, view their live watermarked ID card, and successfully submit valid data.
2. **Photo Validation**: Files over 5MB or below 200x200px are rejected with explanatory error banners.
3. **Tenant Workflow**: Tenant Admin can create batches, configure form fields, generate public links, approve cards, and print duplex A4 sheets.
4. **Zero Build Errors**: Project compiles cleanly with Next.js Turbopack / TypeScript (`npm run build`).
